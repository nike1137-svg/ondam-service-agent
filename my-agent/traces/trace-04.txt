문항 4 — 위치를 안 보내고 취소했을 때 알려 주는가
구분: 경계 경로   ★ 현행 서비스에서 실제로 확인된 구멍

[기록의 성격]  ※ "수정 전"만 실제 확인됨
"수정 전"은 온담이 현행 동작을 그대로 옮긴 것이다. (설계자 확인)
"수정 후"는 아직 실행하지 않았다. 계약을 반영하면 이렇게 되어야 한다는 기준이다.

════════════════════════════════════════
수정 전 — 현행 동작
════════════════════════════════════════

요청        : 리치메뉴 [약정보] → [근처 약국 찾기] → [위치보내기]
              → 구글 지도가 열림 → 어르신이 취소하고 나옴
선택한 도구  : 없음 — 위치가 없어 부르지 않았다 (이 판단 자체는 옳다)
넘긴 인자    : 없음
받은 근거    : 없음
최종 답      : (아무 응답 없음)
종결 신호    : 없음
중단·이관    : 조용히 멈춤. 리치메뉴만 다시 나타남

기대 판정
  도구 선택   : 통과 — 위치가 없을 때 부르지 않은 것은 계약대로다
  스키마 준수 : 해당 없음
  반환 근거   : 해당 없음
  실패 처리   : **실패** — 멈춘 것은 맞지만 멈췄다고 알리지 않았다
  ▶ 기대 판정 : 실패

  실패로 보는 이유
  · 어르신은 답을 기다리시게 된다. 잠시 후 다시 [약정보]를 누르시고,
    또 취소하시고, 반복하다 결국 포기하신다.
  · 리치메뉴 복귀가 시각적 단서이긴 하나, 리치메뉴는 원래 늘 떠 있는 것이라
    "취소됐다"는 뜻으로 읽히지 않는다.
  · **음성으로 쓰시는 분에게는 완전한 침묵이다.**
    글씨를 못 읽으셔서 음성을 쓰시는 분에게 리치메뉴 복귀는 보이지 않는다.
    정작 가장 안내가 필요한 분이 아무것도 듣지 못한다.

════════════════════════════════════════
수정 후 — 설계 패킷 반영
════════════════════════════════════════

요청        : 같음 (지도에서 취소)
선택한 도구  : 없음 — 위치가 없어 부르지 않았다
넘긴 인자    : 없음
받은 근거    : 없음
최종 답      : 괜찮아요, 아무 일도 없었어요.
              약국을 찾으시려면 아래 버튼을 다시 눌러주세요 ✅
              (같은 내용을 음성으로도 들려준다)
종결 신호    : ✅ — 화면과 음성 양쪽
중단·이관    : 재시도하지 않는다. 사용자가 다시 시작할 때까지 기다린다
퀵리플라이   : [ 다시 찾기 ] [ 날씨 보기 ] [ 도움말 ]

기대 판정
  도구 선택   : 통과
  스키마 준수 : 해당 없음
  반환 근거   : 해당 없음
  실패 처리   : 통과 — 멈추고, 멈췄다고 알리고, 다시 시작할 길을 주었다
  ▶ 기대 판정 : 통과

════════════════════════════════════════
무엇이 달라졌나
════════════════════════════════════════

1. 침묵을 없앴다. (설계 기준 4 — 모든 대화는 종결 신호로 끝낸다)
   성공·실패·보류·이관 어느 경로든 예외 없이 적용된다.

2. 음성으로도 알린다. (설계 기준 4 — 음성으로 답할 때도 종결 신호를 준다)
   이모지 ✅ 는 눈으로 보는 신호라, 음성에서는 통째로 사라진다.

3. 사용자를 탓하지 않는다. (설계 기준 5)
   "위치를 보내지 않으셨습니다"가 아니라 "괜찮아요, 아무 일도 없었어요".
   취소는 잘못이 아니다.

4. 자동 재시도를 하지 않는다. (④ 재시도 한도)
   위치 요청을 다시 띄우면 같은 화면에 갇히신다.
