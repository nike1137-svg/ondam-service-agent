문항 1 — 날씨를 숫자가 아니라 말로 전하는가
구분: 정상 경로

[기록의 성격]  ※ 아직 실행하지 않았다
계약을 적용하기 전과 후에 각 문항이 어떻게 처리되어야 하는지를 적은 설계상 기대 기록이다.
실제 실행 로그가 아니다.
"수정 전"은 돌려 본 결과가 아니라 **짐작**이다. 계약이 명문화되지 않아 답이 흔들릴 수 있는
상태를 가정한 것이며, 실제로 그런지는 확인하지 않았다. 반영 후 돌려 보고 채워 넣는다.
"수정 후"는 계약을 반영하면 이렇게 되어야 한다는 기준이다.

════════════════════════════════════════
수정 전 — 계약 없음
════════════════════════════════════════

요청        : 리치메뉴 [날씨] → [위치보내기] → 위치 전송
선택한 도구  : 날씨_확인
넘긴 인자    : 위도 37.5665, 경도 126.9780
받은 근거    : 하늘=맑음, 기온=3, 미세먼지=82, 확인시각=09:10
최종 답      : 오늘은 맑고 기온은 3도입니다.
              미세먼지는 82㎍/㎥입니다.
종결 신호    : 없음
중단·이관    : 해당 없음

기대 판정
  도구 선택   : 통과 — 요청에 맞는 도구를 골랐다
  스키마 준수 : 통과 — 위도·경도가 허용 범위 안에 있다
  반환 근거   : 통과 — 받은 값을 그대로 옮겼다
  실패 처리   : 해당 없음
  ▶ 기대 판정 : 실패

  실패로 보는 이유
  · 숫자를 그대로 내보냈다. 82㎍/㎥가 어느 정도인지 판단을 사용자에게 떠넘겼다.
  · 무엇을 해야 하는지(마스크)가 없다.
  · 종결 신호가 없어 답이 끝난 것인지 알 수 없다.

════════════════════════════════════════
수정 후 — 설계 패킷 반영
════════════════════════════════════════

요청        : 리치메뉴 [날씨] → [위치보내기] → 위치 전송
선택한 도구  : 날씨_확인
넘긴 인자    : 위도 37.5665, 경도 126.9780, 기간 "오늘"
받은 근거    : 하늘=맑음, 기온=3, 미세먼지등급=나쁨, 확인시각=09:10
              (원본 시간별 배열·관측소 코드는 받지 않음)
최종 답      : 오늘은 맑습니다. 쌀쌀하니 겉옷 챙기세요.
              미세먼지가 조금 나쁩니다. 나가실 때 마스크 쓰세요.
              (오전 9시 10분 확인)
              ✅ 다 알려드렸어요
종결 신호    : ✅
중단·이관    : 해당 없음
퀵리플라이   : [ 이번 주 날씨 ] [ 버스 도착 ] [ 도움말 ]

기대 판정
  도구 선택   : 통과
  스키마 준수 : 통과 — 기간 인자를 기본값 "오늘"로 명시
  반환 근거   : 통과 — 등급으로 받아 등급으로 말했다
  실패 처리   : 해당 없음
  ▶ 기대 판정 : 통과

════════════════════════════════════════
무엇이 달라졌나
════════════════════════════════════════

1. 미세먼지 값(82) 대신 등급(나쁨)을 받도록 반환 형식을 좁혔다.
   원본 배열과 관측소 코드는 아예 넘기지 않는다. (⑤ 반환 형식 규약)

2. 숫자에 해석과 행동 권고를 붙였다. "82㎍/㎥" → "조금 나쁩니다, 마스크 쓰세요"
   (설계 기준 2 — 값만 던지면 판단을 사용자에게 떠넘기는 것이다)

3. 확인 시각을 붙였다. 날씨는 시간이 지나면 달라진다. (① 근거 없는 확정 금지 4)

4. 종결 신호 ✅ 와 퀵리플라이 3개를 붙였다. (설계 기준 4)
   오른쪽 끝은 [도움말] 고정.
