문항 5 — 긴급도움을 5분 안에 다시 눌렀을 때
구분: 경계 경로   ★ 현행 서비스에서 실제로 확인된 구멍 — 가장 위험도가 높다

[기록의 성격]
"수정 전"은 온담이 현행 동작을 그대로 옮긴 것이다. (설계자 확인)
[긴급도움]을 누르면 위치와 무관하게 즉시 보호자에게 알림이 나간다.

════════════════════════════════════════
수정 전 — 현행 동작
════════════════════════════════════════

요청        : 14:00:00  리치메뉴 [긴급도움]
              14:01:30  보호자 응답이 없자 [긴급도움] 다시 누름
              14:02:10  또 누름
              14:03:00  또 누름
선택한 도구  : 긴급도움_보호자_알림  ×4회
넘긴 인자    : 보호자=김○○  (위치 없음 — 아직 안 보냄)
받은 근거    : 전송성공 ×4, 전송시각 14:00:00 / 14:01:30 / 14:02:10 / 14:03:00
최종 답      : (매번 같은 답)
              걱정마세요. 보호자에게 즉시 연락했어요.
              위치를 보내주시면 더 빠르게 도와드릴 수 있어요.
종결 신호    : 있음 — "보호자에게 즉시 연락했어요"
중단·이관    : 없음. 네 번 모두 실제로 알림이 나감

판정
  도구 선택   : 통과 — 요청에 맞는 도구를 골랐다
  스키마 준수 : 통과 — 위치는 선택 인자이므로 없어도 유효하다
  반환 근거   : 통과 — 전송 성공을 근거로 답했다
  실패 처리   : **실패** — 재시도 한도가 없다
  ▶ 문항 판정 : 실패

  실패 이유
  · 보호자 휴대폰에 3분 사이 알림이 4개 쌓인다.
    보호자는 상황이 네 배로 심각한 줄 알거나, 반대로 오작동으로 여겨 무시한다.
    둘 다 나쁘고, 두 번째가 더 위험하다.
  · 되돌릴 수 없는 쓰기 동작이 한도 없이 반복됐다.
    과제가 경고한 "같은 호출을 계속하는 중단 없는 순환"에 해당한다.
  · 답이 매번 똑같아서, 어르신은 앞의 요청이 갔는지 안 갔는지 알 수 없다.
    종결 신호가 있어도 **상태가 갱신되지 않으면** 다시 누르게 된다.

════════════════════════════════════════
수정 후 — 설계 패킷 반영
════════════════════════════════════════

요청        : 14:00:00  [긴급도움]
              14:01:30  [긴급도움] 다시 누름
선택한 도구  : 1회차 — 긴급도움_보호자_알림
              2회차 — **부르지 않는다** (5분 억제)
넘긴 인자    : 1회차 보호자=김○○
받은 근거    : 1회차 전송성공, 전송시각 14:00:00, 받은보호자=김○○
              2회차 앞서 보낸 알림의 상태만 조회
최종 답      : [1회차]
              걱정마세요. 보호자에게 즉시 연락했어요.
              위치를 보내주시면 더 빠르게 도와드릴 수 있어요.
              [ 위치보내기 ] [ 119 전화 ] [ 도움말 ]

              [2회차]
              아까 2시 정각에 김○○님께 알렸어요.
              아직 기다리는 중입니다. 조금만 더 기다려 주세요.
              급하시면 아래 119 버튼을 눌러주세요 ✅
              [ 잘못 눌렀어요 ] [ 119 전화 ] [ 도움말 ]
종결 신호    : ✅ — 2회차는 **상태가 갱신된** 답을 준다
중단·이관    : 2회차는 도구를 부르지 않고 중단.
              급한 경우를 위해 119 버튼을 함께 제시 (이관)

판정
  도구 선택   : 통과 — 2회차에 부르지 않은 것이 옳다
  스키마 준수 : 통과
  반환 근거   : 통과 — 앞선 전송 시각과 보호자 이름을 근거로 답했다
  실패 처리   : 통과 — 재시도 한도(5분)를 지켰고, 대체 경로를 주었다
  ▶ 문항 판정 : 통과

════════════════════════════════════════
무엇이 달라졌나
════════════════════════════════════════

1. 5분 안의 중복 호출을 억제했다. (③ 권한과 승인 / ④ 재시도 한도)
   읽기 도구 셋은 몇 번을 불러도 안전하지만, 이 도구만은 다르다.

2. 두 번째 답을 **다르게** 만들었다. 이것이 핵심이다.
   같은 답을 반복하면 상태가 갱신되지 않아, 어르신은 계속 누르신다.
   "아까 2시 정각에 알렸어요"처럼 앞선 요청을 되짚어 줘야 멈추실 수 있다.

3. [잘못 눌렀어요] 버튼을 넣었다. (③ 승인의 자리를 뒤로 옮기기)
   이 도구는 승인을 앞에 두지 않았다. 급할 때 "정말 보낼까요?"를 묻는 것이
   더 위험하기 때문이다. 대신 나간 뒤에 정정할 길을 둔다.
   누르면 보호자에게 "괜찮으시답니다" 후속 메시지가 나간다.

4. 119 버튼을 계속 노출한다.
   중복을 막되, 정말 급한 경우가 막히면 안 된다. 억제와 이관은 함께 가야 한다.
