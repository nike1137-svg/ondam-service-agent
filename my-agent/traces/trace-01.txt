문항 1 — 날씨를 숫자가 아니라 말로 전하는가
구분: 정상 경로
시험하는 계약: ②-2 "숫자를 그대로 내보내지 않는다"

[기록의 성격]  ※ "수정 전"은 실제로 돌려 본 결과다
2026-08-27 온담이에 직접 물어 나온 답을 옮겼다. (설계자 확인)
문구는 화면에서 옮겨 적은 것이라 줄바꿈은 다를 수 있다.
"수정 후"는 아직 실행하지 않았다. 계약을 반영하면 이렇게 되어야 한다는 기준이다.

════════════════════════════════════════
수정 전 — 실제 동작
════════════════════════════════════════

요청        : 리치메뉴 [오늘 날씨] → 위치
선택한 도구  : 날씨_확인
받은 근거    : (화면에 드러난 것) 하늘=흐림, 기온=26.8, 체감=31.0, 미세먼지=17㎍/㎥
최종 답      : 오늘 서울 날씨 26.8도 흐림, 체감 31.0도.
              미세먼지 17㎍/㎥.
              얇은 옷 추천드려요.
말없이 끝나나 : 아니다 — 답이 왔으므로 그 자체가 끝이다
확인 시각    : 메시지 전송 시각이 자동으로 붙는다
중단·이관    : 해당 없음

기대 판정
  도구 선택   : 통과 — 요청에 맞는 도구를 골랐다
  스키마 준수 : 통과
  반환 근거   : 통과 — 받은 값을 근거로 답했다
  실패 처리   : 해당 없음
  ▶ 기대 판정 : **실패**

  실패로 보는 이유
  · **미세먼지를 `17㎍/㎥`로 그대로 내보냈다.** 이것이 이 문항의 핵심이다.
    17은 "좋음"인데, 그 판단을 어르신께 떠넘겼다. ㎍/㎥ 라는 단위도 읽기 어렵다.
  · 기온이 `26.8도`, 체감이 `31.0도`다. 소수점 한 자리는 어르신께 아무 정보도 아니다.
    `.0`은 특히 그렇다. 읽을 것만 늘어난다.

  짚어 둘 것 — 짐작보다 나았던 부분
  · `얇은 옷 추천드려요` — **행동 권고가 이미 있다.**
    처음에 이 트레이스를 짐작으로 쓸 때는 "값만 던지고 끝난다"고 적었는데 틀렸다.
    기온 쪽은 해석해서 전하고 있고, 미세먼지 쪽만 못 하고 있는 상태다.
  · 답이 짧고 한 화면에 들어온다. 설계 기준 1을 이미 지키고 있다.

════════════════════════════════════════
수정 후 — 설계 패킷 반영 (아직 실행 안 함)
════════════════════════════════════════

요청        : 같음
선택한 도구  : 날씨_확인
넘긴 인자    : 위도·경도, 기간 "오늘"
받은 근거    : 하늘=흐림, 기온=27, 체감=31, 미세먼지등급=좋음
              (원본 수치·시간별 배열·관측소 코드는 받지 않음)
최종 답      : 오늘 서울은 흐려요. 27도쯤 되는데 체감은 31도라 덥습니다.
              얇은 옷 입고 나가세요.
              미세먼지는 깨끗합니다. 나들이 다녀오셔도 좋겠어요.
말없이 끝나나 : 아니다 — 답이 왔다. 별도 종결 표시를 붙이지 않는다
확인 시각    : 본문에 쓰지 않는다. 메시지 시각으로 충분하고, 날씨는 몇 분 차이가 의미 없다
퀵리플라이   : 대화 맥락에서 생성 + 오른쪽 끝 [❓도움말]

기대 판정
  도구 선택   : 통과
  스키마 준수 : 통과
  반환 근거   : 통과 — 등급으로 받아 등급으로 말했다
  실패 처리   : 해당 없음
  ▶ 기대 판정 : 통과

════════════════════════════════════════
무엇이 달라지나
════════════════════════════════════════

1. 미세먼지를 **등급으로 받아 등급으로 말한다.** (⑤ 반환 형식 규약)
   `17㎍/㎥` → `깨끗합니다. 나들이 다녀오셔도 좋겠어요`
   값을 받아 놓고 답에서만 바꾸는 것이 아니라, **애초에 등급으로 받는다.**
   원본 수치가 손에 없으면 실수로 내보낼 일도 없다.

2. 소수점을 없앤다. `26.8도` → `27도쯤`, `31.0` → `31도`
   0.8도 차이로 달라지는 행동은 없다. 읽는 품만 든다. (설계 기준 2)

3. 확인 시각을 본문에 넣지 않는다. (⑤)
   메신저가 메시지 시각을 자동으로 붙이고, 날씨는 몇 분 지나도 같다.
   버스와 다른 점이 여기다. 버스는 1~2분에 바뀌므로 본문에 넣는다.

4. 종결 표시를 붙이지 않는다. (설계 기준 4)
   처음 이 트레이스에는 `✅ 다 알려드렸어요`를 붙였는데, 온담이는 대화형이다.
   답변마다 완료 표시를 다는 것은 대화가 아니라 보고서다. **답이 온 것 자체가 끝이다.**

5. 행동 권고는 **이미 있으므로 그대로 둔다.** 미세먼지 쪽에도 같은 방식을 붙일 뿐이다.
