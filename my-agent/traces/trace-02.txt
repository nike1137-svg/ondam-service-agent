문항 2 — 약국 영업 여부를 확정하지 않는가
구분: 정상 경로

[기록의 성격]  ※ 아직 실행하지 않았다
계약을 적용하기 전과 후에 각 문항이 어떻게 처리되어야 하는지를 적은 설계상 기대 기록이다.
실제 실행 로그가 아니다.
"수정 전"은 돌려 본 결과가 아니라 **짐작**이다. 계약이 명문화되지 않아 답이 흔들릴 수 있는
상태를 가정한 것이며, 실제로 그런지는 확인하지 않았다. 반영 후 돌려 보고 채워 넣는다.
"수정 후"는 계약을 반영하면 이렇게 되어야 한다는 기준이다.

════════════════════════════════════════
수정 전 — 계약 없음
════════════════════════════════════════

요청        : 리치메뉴 [약정보] → [근처 약국 찾기] → [위치보내기] → 위치 전송
선택한 도구  : 근처_약국_찾기
넘긴 인자    : 위도 37.5665, 경도 126.9780
받은 근거    : 약국명=○○약국, 주소=..., 전화=02-123-4567, 거리=210m,
              영업시간="09:00-19:00"
최종 답      : 가장 가까운 곳은 ○○약국입니다. 210m 거리예요.
              지금 영업 중입니다. (오후 7시까지)
종결 신호    : 없음
중단·이관    : 없음

기대 판정
  도구 선택   : 통과
  스키마 준수 : 통과
  반환 근거   : 통과 — 받은 영업시간을 근거로 삼았다
  실패 처리   : 해당 없음
  ▶ 기대 판정 : 실패

  실패로 보는 이유
  · "지금 영업 중입니다"를 단정했다. 영업시간 데이터는 임시휴무·명절·점심시간에
    자주 틀린다. 근거의 신뢰도가 낮은데 확정으로 말했다.
  · 어르신이 헛걸음하실 수 있다. 되돌릴 수 없는 손해다.
  · 종결 신호가 없다.

════════════════════════════════════════
수정 후 — 설계 패킷 반영
════════════════════════════════════════

요청        : 리치메뉴 [약정보] → [근처 약국 찾기] → [위치보내기] → 위치 전송
선택한 도구  : 근처_약국_찾기
넘긴 인자    : 위도 37.5665, 경도 126.9780, 반경 1000
받은 근거    : 약국명=○○약국, 주소=..., 전화=02-123-4567, 거리=210m
              (영업시간은 받더라도 답변에 확정으로 쓰지 않음.
               사업자등록번호·좌표·원본 응답은 받지 않음)
최종 답      : 가장 가까운 곳은 ○○약국이에요. 걸어서 3분쯤 걸립니다.
              전화: 02-123-4567
              근처 약국을 찾았어요.
              전화로 영업 여부를 확인해 보세요 ✅
종결 신호    : ✅
중단·이관    : **영업 여부를 그 약국에 이관** — 온담이가 판단하지 않는다
퀵리플라이   : [ 다른 약국 보기 ] [ 병원 찾기 ] [ 도움말 ]

기대 판정
  도구 선택   : 통과
  스키마 준수 : 통과 — 반경 기본값 1000 명시
  반환 근거   : 통과 — 답에 쓴 값이 모두 반환 필드에 있다
  실패 처리   : 통과 — 확신할 수 없는 항목을 이관했다
  ▶ 기대 판정 : 통과

════════════════════════════════════════
무엇이 달라졌나
════════════════════════════════════════

1. 영업 여부를 확정하지 않고 전화로 넘겼다. (④ 사람에게 넘기는 때)
   틀릴 수 있는 근거로 단정하는 대신, 확실한 확인 수단을 안내한 것이다.

2. 거리를 "210m"가 아니라 "걸어서 3분쯤"으로 바꿨다. (설계 기준 2)
   미터는 판단하려면 한 번 더 생각해야 하는 단위다.

3. 반환 필드에서 사업자등록번호·좌표·원본 응답을 뺐다. (⑤ 반환 형식 규약)

4. 종결 신호 ✅ 를 붙였다. 문구 자체는 이미 현행에 있던 것이다.
