문항 6 — 막차 이후 버스를 물었을 때
구분: 경계 경로

[기록의 성격]  ※ 아직 실행하지 않았다
계약을 적용하기 전과 후에 각 문항이 어떻게 처리되어야 하는지를 적은 설계상 기대 기록이다.
실제 실행 로그가 아니다.
"수정 전"은 돌려 본 결과가 아니라 **짐작**이다. 계약이 명문화되지 않아 답이 흔들릴 수 있는
상태를 가정한 것이며, 실제로 그런지는 확인하지 않았다. 반영 후 돌려 보고 채워 넣는다.
"수정 후"는 계약을 반영하면 이렇게 되어야 한다는 기준이다.
같은 "결과 0건"이라도 다음 행동이 다르면 다른 말로 전해야 한다는 계약을 확인하는 문항이다.

════════════════════════════════════════
수정 전 — 계약 없음
════════════════════════════════════════

요청        : 새벽 1시 10분, 리치메뉴 [버스] → [위치보내기] → 위치 전송
선택한 도구  : 버스_도착_확인
넘긴 인자    : 위도 37.5665, 경도 126.9780
받은 근거    : 정류장=중앙시장, 도착정보=[] (0건)
최종 답      : 지금 버스 정보를 확인할 수 없습니다.
              잠시 후 다시 시도해 주세요.
종결 신호    : 없음
중단·이관    : 없음

기대 판정
  도구 선택   : 통과
  스키마 준수 : 통과
  반환 근거   : 통과 — 0건을 근거로 답했다
  실패 처리   : **실패** — 빈 결과를 오류로 뭉뚱그렸다
  ▶ 기대 판정 : 실패

  실패로 보는 이유
  · 막차가 끊긴 것과 조회가 안 되는 것은 다르다.
    "잠시 후 다시 시도해 주세요"는 **기다리라는 뜻**으로 읽힌다.
  · 새벽에 어르신이 오지 않을 버스를 정류장에서 기다리시게 된다.
    추운 날이면 실제 위험으로 이어진다.
  · 무엇을 해야 하는지가 없다. 택시나 다른 방법을 안내하지 않았다.

════════════════════════════════════════
수정 후 — 설계 패킷 반영
════════════════════════════════════════

요청        : 새벽 1시 10분, 리치메뉴 [버스] → [위치보내기] → 위치 전송
선택한 도구  : 버스_도착_확인
넘긴 인자    : 위도 37.5665, 경도 126.9780, 반경 500
받은 근거    : 정류장=중앙시장, 도착정보=[] (0건),
              운행상태=막차종료, 첫차=05:20, 확인시각=01:10
최종 답      : 중앙시장 정류장은 오늘 버스가 끊겼어요.
              첫차는 아침 5시 20분에 옵니다.
              지금 나가셔야 하면 택시를 부르시는 게 좋겠어요 ❌
종결 신호    : ❌
중단·이관    : 0건을 오류로 처리하지 않고 **막차 종료로 구분**해 안내
퀵리플라이   : [ 택시 부르기 ] [ 첫차 알림 받기 ] [ 도움말 ]

기대 판정
  도구 선택   : 통과
  스키마 준수 : 통과
  반환 근거   : 통과 — 운행상태와 첫차 시각을 근거로 삼았다
  실패 처리   : 통과 — 빈 결과의 종류를 갈라 다르게 말했다
  ▶ 기대 판정 : 통과

════════════════════════════════════════
무엇이 달라졌나
════════════════════════════════════════

1. 빈 결과를 두 갈래로 나눴다. (④ 같은 빈 결과라도 다르게 말한다)
   · 막차 이후 0건  → "오늘은 버스가 끊겼어요"  (기다리시면 안 된다)
   · 낮 시간대 0건  → "지금 확인이 안 됩니다"    (조금 뒤 다시 보면 된다)

   같은 데이터인데 어르신이 할 일이 정반대다. 뭉뚱그리면 위험한 쪽으로 실수한다.

2. 반환 필드에 운행상태와 첫차 시각을 추가했다.
   막차 여부를 판단하려면 이 두 값이 필요하다. 없으면 구분 자체가 불가능하다.

3. 다음에 할 수 있는 일을 주었다. (설계 기준 4)
   "버스가 없다"에서 끝나면 어르신은 그 자리에 멈추신다.
   택시라는 대안과 첫차 시각까지 있어야 움직이실 수 있다.

4. 종결 신호를 ❌ 로 했다.
   원하시던 답을 못 드렸으니 ✅ 가 아니다. 다만 **끝났다는 것은 분명히** 알린다.
   (설계 기준 4 — 못 찾았을 때도 반드시 신호를 준다)
