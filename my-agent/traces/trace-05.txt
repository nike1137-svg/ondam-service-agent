문항 5 — 긴급도움을 다시 눌렀을 때 답이 바뀌는가
구분: 경계 경로   ★ 현행 서비스에서 실제로 확인된 구멍

[기록의 성격]
"수정 전"은 온담이 현행 동작을 그대로 옮긴 것이다. (설계자 확인)
[긴급도움]을 누르면 위치와 무관하게 즉시 보호자에게 알림이 나간다.

[이 문항에서 다루는 것]
알림을 막는 문제가 아니다. 급할 때 막히면 그것이 더 위험하다.
다루는 것은 **"갔는지 모르는 상태"** 다. 답이 매번 똑같으면 갔는지 알 수 없다.

그리고 **반복해 누르는 것은 고쳐야 할 행동이 아니다.**
급할 때 보호자에게 알리려 필사적인 것은 당연하고,
그 경황에 버튼을 찾아 누르셨다는 것 자체가 다행한 일이다.
그래서 목표는 누름을 멈추게 하는 것이 아니라 **안심시키는 것**이다.

════════════════════════════════════════
수정 전 — 현행 동작
════════════════════════════════════════

요청        : 14:00:00  리치메뉴 [긴급도움]
              14:01:30  보호자 응답이 없자 [긴급도움] 다시 누름
              14:02:10  또 누름
              14:03:00  또 누름
선택한 도구  : 긴급도움_보호자_알림  ×4회
넘긴 인자    : 보호자=김○○  (위치 없음 — 아직 안 보냄)
받은 근거    : 전송성공 ×4, 전송시각 14:00:00 / 14:01:30 / 14:02:10 / 14:03:00
최종 답      : (네 번 모두 같은 답)
              걱정마세요. 보호자에게 즉시 연락했어요.
              위치를 보내주시면 더 빠르게 도와드릴 수 있어요.
종결 신호    : 있음 — "보호자에게 즉시 연락했어요"
중단·이관    : 없음

판정
  도구 선택   : 통과 — 요청에 맞는 도구를 골랐다. 매번 부른 것도 옳다
  스키마 준수 : 통과 — 위치는 선택 인자이므로 없어도 유효하다
  반환 근거   : 통과 — 전송 성공을 근거로 답했다
  실패 처리   : **실패** — 답이 갱신되지 않는다
  ▶ 문항 판정 : 실패

  실패 이유
  · 종결 신호는 있지만 **네 번 모두 같은 문장**이다.
    어르신 입장에서는 방금 누른 것이 간 건지, 아까 것이 그대로 떠 있는 건지 알 수 없다.
  · 알 수 없으니 다시 누르신다. 침묵이 아니라 **변하지 않는 답**이 같은 결과를 낳는다.
  · 보호자 휴대폰에는 3분 사이 알림이 4개 쌓이는데, 그것이 몇 번째 요청인지 표시가 없다.
    보호자는 시스템 오작동으로 여겨 무시할 수 있다. 급할 때 무시당하는 것이 가장 위험하다.
  · 어르신을 안심시키는 말이 없다. 첫 답과 똑같은 안내만 반복될 뿐이다.

════════════════════════════════════════
수정 후 — 설계 패킷 반영
════════════════════════════════════════

요청        : 14:00:00  [긴급도움]
              14:01:30  [긴급도움] 다시 누름
선택한 도구  : 긴급도움_보호자_알림  ×2회
              **두 번째도 부른다. 막지 않는다**
넘긴 인자    : 1회차 보호자=김○○
              2회차 보호자=김○○, 요청횟수=2  (횟수는 보호자 알림에만 쓴다)
받은 근거    : 1회차 전송성공, 전송시각 14:00:00, 받은보호자=김○○
              2회차 전송성공, 전송시각 14:01:30, 받은보호자=김○○, 누적요청=2
최종 답      : [1회차]
              걱정마세요. 보호자에게 즉시 연락했어요.
              위치를 보내주시면 더 빠르게 도와드릴 수 있어요.
              [ 위치보내기 ] [ 119 전화 ] [ 도움말 ]

              [2회차 — 위치를 아직 안 보낸 경우]
              김○○님께 다시 알렸어요. 잘 전달됐습니다.
              곧 연락하실 거예요. 편한 데 앉아서 기다려 주세요.
              급하시면 아래 119 버튼을 눌러주세요 ✅
              [ 위치보내기 ] [ 119 전화 ] [ 도움말 ]

              [2회차 — 위치를 이미 보낸 경우]
              (문구는 위와 같음)
              [ 잘못 눌렀어요 ] [ 119 전화 ] [ 도움말 ]

              [보호자에게 가는 알림]
              1회차 — 어머님이 도움을 요청하셨어요. (14:00)
              2회차 — 어머님이 다시 요청하셨어요. 2번째 요청입니다. (14:01)
종결 신호    : ✅ — 2회차는 **내용이 바뀐** 답을 준다
중단·이관    : 막지 않는다. 다만 119 버튼을 계속 노출해 다른 길을 함께 둔다

판정
  도구 선택   : 통과 — 두 번째도 부른 것이 옳다. 급할 때 막으면 안 된다
  스키마 준수 : 통과 — 요청횟수 인자를 추가로 넘겼다
  반환 근거   : 통과 — 보낸 시각과 보호자 이름을 근거로 답했다.
                누적요청 값은 보호자 알림에만 썼고 어르신 답변에는 쓰지 않았다
  실패 처리   : 통과 — 답이 갱신되고, 정정할 길과 대체 경로를 함께 주었다
  ▶ 문항 판정 : 통과

  통과 기준 하나 더
  · "지금까지 2번 알렸습니다"처럼 **어르신께 횟수를 세면 실패다.**
    세는 말은 나무라는 말로 들린다. (설계 기준 5)

════════════════════════════════════════
무엇이 달라졌나
════════════════════════════════════════

1. 알림을 막지 않는다. 이것이 이 문항의 핵심 판단이다.
   (③ 권한과 승인 / ④ 재시도 한도)

   읽기 도구 셋은 실패하면 온담이가 알아서 1회 다시 부른다.
   긴급도움은 스스로 다시 보내지 않는다. 사람이 버튼을 누를 때만 나간다.
   그리고 사람이 누른 것은 재시도가 아니라 **새 요청**이므로 횟수를 제한하지 않는다.

2. 두 번째 답을 **바꾸되, 횟수는 말하지 않는다.**

   같은 답이 다시 뜨면 갔는지 알 수 없으니 답은 바뀌어야 한다.
   그러나 "2번 알렸습니다"는 세는 말이고, 세는 말은 나무라는 말로 들릴 수 있다.

   반복해 누르는 것은 고쳐야 할 행동이 아니다.
   그래서 목표를 "누름을 멈추게 하기"가 아니라 **"안심시키기"** 로 잡았다.
   갔다는 사실과, 지금 무엇을 하시면 되는지를 말한다.
   "편한 데 앉아서"는 넘어짐을 막는 말이기도 하다.

3. 보호자에게 가는 알림에만 **몇 번째 요청인지** 붙였다.
   표시가 없으면 알림 4개가 오작동으로 보인다. "2번째 요청"이 붙으면
   같은 4개가 "급한 상황"으로 읽힌다. 같은 알림인데 읽히는 뜻이 달라진다.
   횟수가 필요한 쪽은 보호자이지 어르신이 아니다.

4. 퀵리플라이 3칸을 **위치 전송 여부에 따라** 다르게 채웠다.

   | 상태 | 1 | 2 | 3 |
   |------|---|---|---|
   | 위치 아직 안 보냄 | 위치보내기 | 119 전화 | 도움말 |
   | 위치 이미 보냄   | 잘못 눌렀어요 | 119 전화 | 도움말 |

   3칸뿐인데 필요한 버튼은 넷이다. 위치를 안 보낸 분에게 [위치보내기]가 사라지면
   보낼 길이 없어지고, 이미 보낸 분에게는 그 칸이 쓸모없다.
   상황마다 꼭 필요한 것만 남긴다.

5. [잘못 눌렀어요] 버튼을 넣었다. (③ 승인의 자리를 뒤로 옮기기)
   이 도구는 승인을 앞에 두지 않았다. 급할 때 "정말 보낼까요?"를 묻는 것이
   더 위험하기 때문이다. 대신 나간 뒤에 정정할 길을 둔다.
   누르면 보호자에게 "괜찮으시답니다" 후속 메시지가 나간다.

6. 119 버튼을 두 경우 모두에 남겼다.
   보호자가 끝내 응답하지 않을 수 있다. 그때 기댈 곳이 하나는 남아 있어야 한다.
